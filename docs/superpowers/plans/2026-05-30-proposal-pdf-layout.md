# 提案PDFレイアウト・太陽光必須項目 実装計画

日付: 2026-05-30
対象: `src/index.ts` / `src/proposal-simulation-validation.test.ts` / Notion 提案シミュレーションDB

## ゴール

太陽光提案PDFを A4 2ページのバランス型構成へ寄せる。太陽光提案では、価格だけでなく、物件特定、設備、売電条件、年間維持費、連系開始日まで入力確認する。空の任意項目はPDFとメモに出さない。

## 実装ステップ

1. テスト追加
   - 太陽光提案の完全入力サンプルを作る。
   - `パネルメーカー` 欠落時に `入力待ち` になることを確認する。
   - `連系開始日` 欠落時に `入力待ち` になることを確認する。
   - 年間維持費の合計入力と内訳自動合算を確認する。
   - `年間手残り`、利回り、回収年数、2ページPDFを確認する。
   - 蓄電池提案には太陽光設備項目を強制しないことを確認する。

2. Worker本体
   - `ProposalSimulationDraft` に太陽光設備情報、年間手残り、維持費内訳を追加する。
   - 太陽光提案だけに必須チェックを追加する。
   - `年間維持費（ランニングコスト）` は合計を優先し、なければ入力済み内訳を合算する。
   - `稼働年数` は `連系開始日` から自動計算する。
   - `年間手残り = 年間売電収入 - 年間維持費` を主要数字として扱う。

3. PDF/メモ構成
   - 1ページ目は物件概要、主要数字、提案タイプ別結論。
   - 2ページ目は設備、売電条件、維持費内訳、リスク・次アクション。
   - PDFは既存の `pdf-lib` 方式を維持し、英字ラベル中心の安全な2ページ出力にする。

4. Notion側
   - 提案シミュレーションDBに不足している太陽光入力項目を追加する。
   - 入力例レコードへテスト用の値を補完し、ボタン実行で二度手間にならない状態にする。

5. 検証
   - `npm run test:proposal-simulation-validation`
   - `npm run check`
   - `npm run build`
   - サンプルPDFをレンダリングして目視確認する。
   - `NOTION_KEYRING=0 npx ntn workers deploy`
   - 実レコードでWorkerを実行し、PDF保存とステータス更新を確認する。

## 注意

`wajo-notion-workers` は現時点でgit管理外の作業ディレクトリなので、コミットやworktreeではなく、差分ファイルと検証結果で引き継ぐ。
