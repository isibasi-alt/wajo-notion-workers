# 失注システム Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 営業マンが正本ステータスを直接「失注」に変えず、問い合わせ・案件それぞれの重さに応じて失注理由、処理者、処理日、申請/監査ログを必ず残す。

**Architecture:** 正本ステータスは営業ビューから隠し、営業は表示専用ミラーと失注ボタンだけを見る。問い合わせは `失注理由必須 + 通知/監査ログ`、案件は `失注申請中 + マネージャー承認` を基本にし、Worker が条件チェックとログ作成を担う。案件の失注対応窓口はマネージャーだけに集約し、申請・承認・差し戻しの事実は全員に通知する。

**Tech Stack:** Notion DB / Notion Button / `@notionhq/workers` / TypeScript / `ntn workers deploy`

## Task 2: Workerの失注共通ロジックを追加する

**先生側**
- [ ] `src/index.ts` に失注理由抽出関数を追加する。
  - Webhook body の `失注理由`, `lostReason`, `reason` を読む。
  - 空なら `needs-lost-reason` を返し、ステータスを変えない。
- [ ] `processInquiryLostWebhook` を追加する。
  - 問い合わせは理由必須。
  - `ステータス = 失注`、`失注日`、`失注処理者`、`失注前フェーズ`、`失注ログ` を更新する。
  - 営業部または管理者向けコメント通知を残す。
- [ ] `processProjectLostRequestWebhook` を追加する。
  - 案件は理由必須。
  - 営業ボタンでは `ステータス = 失注申請中`、`失注申請状態 = 申請中` までに止める。
  - `失注理由`、`失注理由メモ`、`失注前フェーズ`、`失注処理者` を残す。
  - 申請が出た時点で営業部全員へ通知コメントを残す。
- [ ] `processProjectLostApproveWebhook` を追加する。
  - マネージャー確認後に `ステータス = ❌ 失注`、`失注申請状態 = 承認済`、`失注日` を入れる。
  - 承認後も営業部全員へ通知コメントを残し、`失注申請中` と `❌ 失注` の差分を見えるようにする。
- [ ] `processProjectLostRejectWebhook` を追加する。
  - `失注申請状態 = 差し戻し`、ステータスは元フェーズまたは `⏳ 確認待ち` へ戻す。
  - 差し戻し時も営業部全員へ通知コメントを残す。

**石橋さん側**
- [ ] Notionボタン名を決める。
  - 問い合わせ: `失注にする`
  - 案件営業用: `失注申請する`
  - 案件マネージャー用: `失注を承認する` / `失注を差し戻す`
