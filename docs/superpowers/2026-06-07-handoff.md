## 5. ★いま中断中のタスク：企業マスターのページUIをタブ→セクションへ作り替え

公式ドキュメントで判明した重要事実（裏取り済 https://www.notion.com/help/layouts ）:

* Notionタブ付きレイアウトは「コンテンツタブは1つだけ（＝詳細タブ。ページ自身のプロパティを出せる唯一のタブ）」。追加タブはデータベースのビュー専用。
* だから大ちゃんが作った「連絡先タブ/与信タブ」に企業マスターDBを指定→全企業ギャラリーが出てしまった（外せない元凶）。「詳細スタイルのタブを複数」はNotion非対応。1.5時間ハマったのはこのため（大ちゃんのスキルのせいではない）。

正解の構造（合意済）: 連絡先・与信は"タブ"でなく**"詳細(コンテンツ)タブの中のセクション=プロパティグループ"**にする：

```
詳細タブ(唯一のコンテンツタブ)
├─ ヘッダー(ピン留め: 企業調査ステータス/信頼度/提案可否/代表者 等)
├─ ▼連絡先         (先方担当者/面談相手/連絡可否/電話番号/メール/ウェブサイトURL/X/LinkedIn/住所/住所マップ)
├─ ▼与信・基本情報  (資本金/売上規模/従業員規模/設立年月/上場区分/法人番号/TDB各項目/信頼度/リサーチ最終実行日)
└─ ▼深掘りドシエ    (企業サマリー/現在・将来課題仮説/営業切り口/和上解決策適合/3C×3/経営陣/役員SNS/直近ニュース/再エネ接点/想定決裁者/想定反論/出典ソース)
商談 / 商談準備レポート / 関連 タブ ← これはDBビュータブのままでOK(関連レコード表示=正しい用途)
```

残作業: ①不要な「連絡先/与信ビュータブ(全企業ギャラリー)」をカスタマイズ画面で削除(各タブの「…」→ビュー削除)。②詳細タブ内にプロパティグループのセクションを追加("+ パネルに追加"/「＋」→プロパティグループ、右パネルの「+ セクションを追加」)。③各セクションで目アイコン👁で出す項目を選ぶ。

* このセッションでの教訓/詰まり: Notionレイアウト編集はAPI不可＝UI専用。computer-useのピン/＋はクリック判定がシビアでメニュー(プロパティ削除が隣)が出やすく事故リスク。音声入力アプリ「Typeless」がNotionにオーバーレイしてクリックをブロックすることがある(終了させると解決)。Teachモードはこのセッションでは使用不可だった。→ UI作業は「大ちゃんがクリック＋Claudeがスクショ確認」の協働か、慎重な1手ずつが安全。

# ★追補（最優先）＝本題は「営業が使えるデータ」

> この追補が §6 の優先順位を**上書き**する。次スレッドはここを守る。

## A. 北極星（これを見失わない）

本質は **「名刺1枚 → 営業がそのまま商談で話せる"キレキレのトーク"」**。判定基準はただ一つ＝**営業が現場で使えるか**。Notionのタブ/ビューの見た目は"使いやすさの補助"であって本体ではない。**見た目調整に時間を溶かさない。**

「使える」を成立させる3条件：

1. **事実で裏取り**されている（推測の垂れ流しはチープ。事実は出典付き、不明は「推測ですが」と明示）。
2. **和上の武器に接続**されている（800MW実績/系統用蓄電池/発電所仲介/FIP/投資回収。相手の課題→和上の解決策を"数字で"マッピング。プレイブックは実装済）。
3. **量も担保**（基本情報・与信・役員・SNS・直近ニュース・再エネ接点・決裁者・想定反論まで一通り埋まる）。

現状：Perplexity多段リサーチで②③と①の"公開情報"は本番LIVEで出ている。欠けている最後のピース＝**TDB（COSMOSNet）の"確報与信"**。ここが入ると「ピントがズレない」が完成する。

## B. ★CosmosNet（帝国データバンク）— 最終ゴールの詳細

### B-1. なぜ最重要か
Perplexityの公開情報は仮説寄り。対してTDBは信用調査に基づく"確報"の与信。この2つが揃って初めて営業が安心して数字を語れる。具体的にはTDB約8項目：

* **企業評点（評価点）／倒産確率** … 与信スコアの核
* 年商（売上規模）／資本金／従業員数／設立年月／業種／代表者・法人番号 … 会社の骨格

これが入ると、今「暫定（信頼度=中／提案可否=タイミング待ち）」で止まっている `scoreCompany` が**実評点ベースの本物の与信判定**に変わる。ドシエに「TDB評点◯／倒産確率◯%」が載り、商談で裏取り済みの一言が言える＝サービスの格が一段上がる。

### B-2. 技術的な現実（誤解すると詰む）
* COSMOSNetは**Webログイン専用**。公開APIは無い（ID/パスはあり・変更済）。
* Notion Worker（サーバーレス）内ではブラウザを動かせない → COSMOSNet取得は**別の小さな部品（ブラウザ自動操作＝Playwright等）**として切り出す必要がある。
* 方針は **「3番＝ブラウザ自動操作」で合意済**。根拠：低頻度（名刺10-12人/日・1日5-6回程度）、自分名義のID、社内利用、本人が全責任を取る。

### B-3. 完成形の流れ
```
名刺登録
 → ①簡易エンリッチ(Perplexity・自動)
 → ②[ボタン]TDB取得：
      取得部品がCOSMOSNetへ自動ログイン → 企業名/法人番号で検索 → 8項目を取得 → 正規化(TdbProfile)
      → Worker側 fetchTdbProfile() に返す(今は暫定null。ここが差し込み口)
 → ③scoreCompanyが実評点で与信確定(信頼度/提案可否)
 → ④Perplexity多段深掘り(役員/SNS/ニュース/再エネ接点/決裁者)
 → ⑤統合 → 企業マスターの構造化列＋本文ドシエ(出典付き) ＋ トーク土台
```
※②と④は独立。②(TDB)が本確報、④(Perplexity)が周辺情報。両輪。

### B-4. 実装の進め方（盲目でコードを書かない）
1. **実画面マッピングが先**：COSMOSNetのログイン→検索→結果ページのHTML/導線を、大ちゃん立会いで一度実際に辿る（セレクタ/手順を確定）。画面を見ずにスクレイパを書くと"動かない箱"＝今回直したい失敗そのもの。
2. **取得部品の置き場を決める**：常駐Mac上のローカルサービス or ブラウザが動く小さなクラウド関数。認証情報はその部品の環境変数に置く（チャット・コード・Notionには出さない）。
3. **取得部品を実装**：ログイン→検索→8項目抽出→`TdbProfile`型で返すHTTPエンドポイント。
4. **Workerと接続**：`fetchTdbProfile()`（src/index.ts、現在`return null`）をそのエンドポイント呼び出しに差し替え。`tdbToPatches`で構造化列へ、`scoreCompany`で与信確定（実装済・接続するだけ）。
5. **保険（フォールバック）**：自動取得が不安定な時用に「営業がCOSMOSNet帳票をコピペ→AIが8項目を解析」する貼り付け方式も用意可（規約も安全）。

### B-5. 「完了」の定義（証拠で示す）
実在1社で **[ボタン]→TDB8項目が企業マスターの構造化列に入り、与信が"暫定"でなく実評点ベースになり、ドシエに「TDB評点◯/倒産確率◯%」が出る**こと。テスト＋実機のNotion結果で証拠提示してから「完了」と言う。

# ★本日の実機品質監査メモ（2026-06-07 / by Claude）

ライン1の出力を実在1社（株式会社エコスタイル 🧪 `3764d017-81e7-813c-89d0-cd9c8d6a20ca`）でフル確認。**中身の濃さ・正直さは合格**（経営陣実名3名／直近ニュース＝蓄電所提携・アグリゲーターライセンス・三菱HCキャピタル提携まで具体／営業切り口・想定反論がそのまま喋れる／【推測】【確認できませんでした】が明示）。

ただし**「使える3条件①＝事実の見せ方」で構造化列に未達の穴**を発見。Bの書き込み側（`tdbToPatches`/ドシエ書き込み）を触る時に**ついでに潰す**こと（単独で時間を割く優先度ではないが、放置すると"スッキリ"が崩れる）：

1. **構造化列に出典番号と「です」が混入してノイズ化**。短い事実値に `[1][3]` や「です」は営業のコピペで邪魔。
   * `代表者` = `木下 公貴（…）です。[1][3][7]` → `木下 公貴（代表取締役 社長執行役員）`
   * `資本金` = `1,541百万円です。[1]` → `1,541百万円`
   * `設立年月` = `2004年10月5日です。[1][3]` → `2004年10月5日`
   * → **事実値はベタ値**、出典番号は「出典ソース」列／本文ドシエだけに集約。書き込み前に `[\d+]` と末尾「です。」を構造化短値からstripするヘルパを入れる。
2. **住所が構造化と本文で矛盾**。`住所`列=`大阪府大阪市北区` vs サマリー本文=`大阪市中央区道修町…ミフネ道修町ビル3階`。営業が住所欄だけ見ると誤る。**本社所在地は本文の確報値に揃える**（または住所列を本文から導出）。
3. **古いゴミ残り**。`企業AI受付メモ`に旧ロジックのログ「2026-05-22…3Cが揃ったため完了」、`備考`に「検証用ダミー｜削除予定」。実運用前に掃除。
