# TDB課金ボタンのゲーティング設計 ＋ 無料/低コスト代替の調査結果（2026-06-08）

> ミッション(大ちゃん厳命): ①TDB取得ボタンを「管理職のみ×有効取引先のみ」に作り替える。②無料〜ほぼ無料で"質"を担保した企業情報収集でTDBを代替/補完する手法を発掘する。量でなく質。

## 0. 結論（先に核心）

- **TDBの無料完全代替は存在しない。** 信用スコア(評点)・倒産確率に相当する情報は無料APIからは一切取得不可（複数ソースで裏取り済・下記出典）。
- **だが会社の"骨格＋シグナル"は無料で質高く揃う。** これが代替の本体。
- ∴ 正しい設計＝**「無料スタックを既定(全リード)」＋「TDB有料は"評点だけ"のために管理職×有効取引先に限定」**の二層。Part1のゲーティングはこの"限定"を担保する仕組み。

---

## Part 1. TDB課金ボタンのゲーティング設計

### 要件
- (R1) 押下できるのは**管理職のみ**。
- (R2) **有効取引先**(＝見込みが立った/商談化した取引先)に対してのみ動線が出る。
- (R3) 誤課金・乱発の防止（1社1,320〜1,760円の従量、CCRは+3,300円）。

### 現実（Notionの制約）
- Notionの「ボタン」プロパティは**押した人の権限で実行**＝ボタン自体に「管理職だけ」ネイティブ権限は無い。
- 取得部品側には既に**三重安全弁実装済**：`TDB_ALLOW_PURCHASE=1`でなければ購入しない／`TDB_PLAN=basic`既定／同名割れ`ambiguous`で課金停止。これはサーバ運用での"元栓"。

### 設計案（推奨＝A+Cの併用。鉄板ルール=列/ビュー追加は要承認なので★で明示）
- **A. Worker側の資格ゲート（無料・最優先・列追加ほぼ不要）**
  capabilityの冒頭で対象企業ページの既存プロパティを判定し、満たさなければ**課金前に拒否**：
  - 「有効取引先」判定＝既存の `顧客化ステータス`/`関係深度`/`提案可否`/`ステータス` が"有効/商談化"相当か。
  - 満たさない→`{status:"skipped", reason:"not_active_customer"}`を返し**1円も使わない**。
  - これだけでR2とR3の大半を満たす。**列追加ゼロで実装可。**
- **C. 管理職承認の二段化（R1の実効担保）**
  - 営業は「TDB取得を希望」する軽いアクション（例：既存`備考`に申請メモ or ★承認用チェックボックス1個＝要承認）。
  - 実際の課金ボタンは**管理職だけが触れる導線**に置く。Notionネイティブで"管理職のみ"を担保する手段は2択：
    - (C-1) **管理職専用ページ/ビューに課金ボタンを隔離**（営業のビューには出さない）。★ビュー追加=要承認。
    - (C-2) **Worker側で押下者を許可リスト照合**：ボタン→webhookに「実行ユーザー」が乗るかは**要検証**（Notion automation/buttonのpayload仕様）。乗るなら管理職NotionユーザーIDのallowlistでサーバ判定（列追加ゼロ）。乗らなければC-1にフォールバック。
- **B.（不採用寄り）** 全営業に開放＋事後アラート＝乱発リスク高。却下。

### 推奨実装順
1. まず**A（資格ゲート）をWorkerに実装**＝即・無料・列ゼロでR2/R3を満たす。
2. **C-2の可否を検証**（button webhookにユーザーが乗るか）。乗れば許可リストでR1。乗らなければ**C-1（管理職専用ビューに隔離）を承認の上**で1回だけ追加。
3. 取得部品は`TDB_ALLOW_PURCHASE`を本番のみ1に（元栓）。

## Part 2. 無料/低コストでの"質"の代替（検証済）

### 2-1. 確定した事実（出典付き）
- **法人番号API（国税庁）**：無料。基本3情報(法人番号/商号/本店所在地)＋変更履歴。全約500万社。APP ID発行に2週〜1ヶ月・無料。→名寄せ/法人番号確定の土台。
- **gBizINFO（経産省）**：無料(要・無料APIキー)。法人基本(代表者/資本金/従業員/業種/事業概要/設立/HP)＋**財務・補助金・調達(入札)・許認可・表彰・特許**。★限界＝**行政接点(補助金/届出/調達)のある社に厚い**。太陽光・再エネは補助金/FIT/調達の足跡が濃く相性良。2026にデータ項目拡充予定。
- **EDINET API v2（金融庁）**：無料(要キー)。有報のフル財務、2024以降CSV可。★上場・大企業のみ＝中小は対象外。
- **官報決算 / FUMA**：決算公告(売上/利益/純資産)。FUMAが無料・ログイン不要で約160万社集約(出典＝web/国税庁/有報/官報)。
- **Musubu**：無期限無料プランあり・約140万社(本社/事業所/業種/従業員)。
- ★**信用スコア(評点)/倒産確率の無料代替は存在しない**（明確に裏取り）。商用API(SalesNow等)でも信用スコアは有料機能。

### 2-2. 推奨アーキ＝二層
```
【無料スタック=既定・全リード・課金ゼロ・列は既存受け皿に格納】
 法人番号API(名寄せ/法人番号) → gBizINFO(資本金/従業員/設立/代表者/業種/財務/補助金/調達/許認可)
   → EDINET(上場時のみフル財務) → 官報/FUMA(決算公告) → Perplexity(役員/SNS/ニュース/取引先/再エネ接点/決裁者)
   → 自社サイト/IR(確報facts)
   = 骨格＋物語を"質"で充足。出典明示・不明は「推測ですが」。

【有料TDB=管理職×有効取引先のみ(Part1ゲート)】
   COSMOS2で唯一の穴=確報与信(評点/倒産確率)を補完。late-stage qualified dealだけ。
```

### 2-3. 無料"簡易与信シグナル"（評点の代わりに質を担保）
TDB評点は買わずとも、無料データで**方向性のある与信シグナル**を作れる（既存`scoreCompany`を強化）：
- gBizINFO/EDINET/官報の**財務トレンド**（売上・利益・自己資本比率の推移）
- **設立年数**（存続年数）、**資本金**規模
- **補助金採択/調達(入札)実績**＝行政の信用接点(ポジティブシグナル)
- **ネガティブニュース**（Perplexityで訴訟/遅延/リストラ等）
→ これらで `信頼度 high/mid/low` を自動判定。TDB評点ではないが、**大半のリードはこれで判断十分**。TDB評点は最終確報が要る案件だけ。

### 2-4. 実装の次アクション（Part2）
1. **gBizINFOコネクタを新設**（無料・最大の費用対効果）。APIキー取得→`資本金/従業員/設立/代表者/業種/財務/補助金/調達`を取得し既存受け皿列＋ドシエへ。fetchTdbProfileと同じ"枠に差す"流儀。
2. **法人番号API**で法人番号を確定（gBizINFO/TDBの名寄せキー）。APP ID発行はリードタイム長→早めに申請。
3. `scoreCompany`を無料財務シグナルで強化（2-3）。
4. TDB(有料)はPart1ゲートの先に温存。
