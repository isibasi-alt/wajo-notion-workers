# 提案PDF構成デザイン仕様

日付: 2026-05-30
対象: `processProposalSimulationById` / `processProposalSimulationWebhook`

## 目的

太陽光提案PDFを、営業提出に耐える A4 2ページ構成へ寄せる。単なる試算表ではなく、物件の身元、設備概要、売電条件、毎年の維持費、年間手残り、主要リスクが一目で分かる資料にする。

現行の「入力ガード + 試算値PDF」を土台にし、太陽光提案では必要項目が抜けている場合はPDF生成を止めて `入力待ち` に戻す。任意項目は空欄ならPDFから除外する。

## 対象範囲

対象は太陽光提案の3タイプ。

- `法人対象`
- `個人投資家向け`
- `環境配慮型企業向け`

`系統用蓄電池` は既存どおり別の必須項目体系を使う。今回の太陽光設備項目は蓄電池提案には強制しない。

## 太陽光提案の必須項目

価格・収益:

- `販売価格`
- `仕入れ価格`
- `年間売電収入`、または `月間発電量` + `売電単価`
- `年間維持費（ランニングコスト）`

年間維持費は入力負荷を下げるため、合計1項目で通せるようにする。`年間ランニングコスト（合計）` / `年間ランニングコスト` / `ランニングコスト（年）` のいずれかを読む。内訳項目がある場合は入力済み分だけPDFへ表示するが、内訳そのものは必須にしない。

物件特定:

- `発電所名`
- `所在地`
- `電力会社エリア`
- `低圧/高圧区分`

設備:

- `パネルメーカー`
- `パネル型式`
- `パネル枚数`
- `DC容量（パネル側kW）`
- `パワコンメーカー`
- `パワコン型式`
- `PCS容量（パワコン側kW）`

売電・稼働:

- `FIT/FIP区分`
- `売電単価`
- `残存売電期間`
- `連系開始日`

`稼働年数` は `連系開始日` からPDF作成日時点で自動計算する。

## 任意項目と除外ルール

任意項目は空欄ならPDFに出さない。`未入力` という文字列を並べて資料品質を落とさない。

任意表示候補:

- `O&M費`
- `保険料`
- `地代`
- `固定資産税`
- `除草費`
- `監視通信費`
- `年間CO2削減量`
- `年間電気代削減率`
- `年間電気代削減額`
- `融資条件`
- `備考`
- `リスク補足`

ただし、営業判断に関わる不足は `未確認事項` ブロックへ短く出せるようにする。初期実装では、必須不足はPDF生成前に止めるため、PDF内の未確認事項は任意項目由来に限定する。

## PDF構成

採用案は `C. バランス型`。

1ページ目: 物件概要 + 主要数字 + 結論

- タイトル
- 発電所名
- 所在地
- 電力会社エリア
- 低圧/高圧区分
- 販売価格
- 年間売電収入
- 年間維持費（ランニングコスト）
- 年間手残り
- 想定利回り
- 想定回収年数
- 提案タイプ別のひとこと結論

2ページ目: 設備詳細 + 売電条件 + 費用内訳 + リスク

- パネルメーカー / 型式 / 枚数 / DC容量
- パワコンメーカー / 型式 / PCS容量
- FIT/FIP区分
- 売電単価
- 残存売電期間
- 連系開始日
- 稼働年数
- 入力済みの維持費内訳
- 提案タイプ別の注意点
- 任意項目由来の未確認事項

## 計算方針

- `年間手残り = 年間売電収入 - 年間維持費（ランニングコスト）`
- `想定粗利 = 販売価格 - 仕入れ価格`
- `想定利回り = 年間手残り / 販売価格 * 100`
- `想定回収年数 = 販売価格 / 年間手残り`

年間手残りが0以下の場合、利回りと回収年数は無理に良く見せず、要確認として扱う。

## Notion書き戻し

既存の `シミュレーションステータス`、`不足項目`、`シミュレーションメモ`、`御社への結論`、`提案PDF` の流れは維持する。

必須不足時:

- `シミュレーションステータス = 入力待ち`
- `不足項目 = 最初に足りない項目`
- `シミュレーションメモ` に次に確認する項目を表示
- PDFは生成しない

入力完了時:

- `シミュレーションステータス = シミュレーション準備完了`
- `不足項目` を空にする
- `シミュレーションメモ` に主要数字、結論、提案タイプガイドを保存
- `提案PDF` files型へPDFを保存

## テスト方針

`proposal-simulation-validation.test.ts` に次を追加する。

- 太陽光提案で `パネルメーカー` が空なら `入力待ち`
- 太陽光提案で `連系開始日` が空なら `入力待ち`
- 太陽光提案で必須項目が揃うと `年間手残り` を計算する
- 任意の費用内訳が空でもPDF生成は止めない
- PDFは2ページのまま
- 蓄電池提案には太陽光設備必須項目を強制しない

## 実装メモ

現行の `buildProposalSimulationPdfBytes` は `pdf-lib` 標準フォント制約のため英数字中心の安全PDFを出している。今回の初期実装も同じ制約内で、英字ラベルと数値中心のレイアウトを磨く。日本語本文は引き続きNotion側の `シミュレーションメモ` / `御社への結論` に保持する。

将来、営業提出用の完全な日本語PDFにする段階では、Google Docs/Slidesテンプレート連携、または日本語フォント埋め込み可能なPDF生成方式へ切り替える。
